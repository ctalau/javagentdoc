# Class: `TreeTraverser`

**Package:** [`com.google.common.collect`](README.md)

**Fully Qualified Name:** `com.google.common.collect.TreeTraverser`

## Type Parameters

- `T` extends `java.lang.Object`

## Description

Views elements of a type `T` as nodes in a tree, and provides methods to traverse the trees
 induced by this traverser.

 <p>For example, the tree

 <pre>`h
      / | \
     /  e  \
    d       g
   /|\      |
  / | \     f
 a  b  c
 `</pre>

 <p>can be iterated over in preorder (hdabcegf), postorder (abcdefgh), or breadth-first order
 (hdegabcf).

 <p>Null nodes are strictly forbidden.

 <p><b>For Java 8 users:</b> Because this is an abstract class, not an interface, you can't use a
 lambda expression to extend it:

 <pre>`// won't work
 TreeTraverser<NodeType> traverser = node -> node.getChildNodes();
 `</pre>

 Instead, you can pass a lambda expression to the `using` factory method:

 <pre>`TreeTraverser<NodeType> traverser = TreeTraverser.using(node -> node.getChildNodes());
 `</pre>
**Author:** Louis Wasserman
**Since:** 15.0
**Deprecated:**Use `com.google.common.graph.Traverser` instead. All instance methods have
     their equivalent on the result of `Traverser.forTree(tree)` where `tree`
     implements `SuccessorsFunction`, which has a similar API as `children` or can be
     the same lambda function as passed into `using(Function)`.
     <p>This class is scheduled to be removed in October 2019.

## Methods

### `using([`com.google.common.base.Function<T,? extends java.lang.Iterable<T>>`](../base/Function>.md) nodeToChildrenFunction)`

**Returns:** [`com.google.common.collect.TreeTraverser<T>`](./TreeTraverser.md)

Returns a tree traverser that uses the given function to navigate from a node to its children.
 This is useful if the function instance already exists, or so that you can supply a lambda
 expressions. If those circumstances don't apply, you probably don't need to use this; subclass
 `TreeTraverser` and implement its `children` method directly.
**Since:** 20.0
**Deprecated:**Use `com.google.common.graph.Traverser.forTree` instead. If you are using a
     lambda, these methods have exactly the same signature.

### `children(`T` root)`

**Returns:** `java.lang.Iterable<T>`

Returns the children of the specified node. Must not contain null.

### `preOrderTraversal(`T` root)`

**Returns:** [`com.google.common.collect.FluentIterable<T>`](./FluentIterable.md)

Returns an unmodifiable iterable over the nodes in a tree structure, using pre-order traversal.
 That is, each node's subtrees are traversed after the node itself is returned.

 <p>No guarantees are made about the behavior of the traversal when nodes change while iteration
 is in progress or when the iterators generated by `children` are advanced.
**Deprecated:**Use `com.google.common.graph.Traverser.depthFirstPreOrder` instead, which has
     the same behavior.

### `preOrderIterator(`T` root)`

**Returns:** [`com.google.common.collect.UnmodifiableIterator<T>`](./UnmodifiableIterator.md)

### `postOrderTraversal(`T` root)`

**Returns:** [`com.google.common.collect.FluentIterable<T>`](./FluentIterable.md)

Returns an unmodifiable iterable over the nodes in a tree structure, using post-order
 traversal. That is, each node's subtrees are traversed before the node itself is returned.

 <p>No guarantees are made about the behavior of the traversal when nodes change while iteration
 is in progress or when the iterators generated by `children` are advanced.
**Deprecated:**Use `com.google.common.graph.Traverser.depthFirstPostOrder` instead, which
     has the same behavior.

### `postOrderIterator(`T` root)`

**Returns:** [`com.google.common.collect.UnmodifiableIterator<T>`](./UnmodifiableIterator.md)

### `breadthFirstTraversal(`T` root)`

**Returns:** [`com.google.common.collect.FluentIterable<T>`](./FluentIterable.md)

Returns an unmodifiable iterable over the nodes in a tree structure, using breadth-first
 traversal. That is, all the nodes of depth 0 are returned, then depth 1, then 2, and so on.

 <p>No guarantees are made about the behavior of the traversal when nodes change while iteration
 is in progress or when the iterators generated by `children` are advanced.
**Deprecated:**Use `com.google.common.graph.Traverser.breadthFirst` instead, which has the
     same behavior.
